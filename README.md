# Indonesia Economic Dashboard

Three static pages built from Bank Indonesia and BPS data, published via GitHub Pages:

- **GDP** — https://anshory1972.github.io/econdashboard/html/econdashboard.html
- **Balance of Payments** — https://anshory1972.github.io/econdashboard/html/bop.html
- **Financial Markets** — https://anshory1972.github.io/econdashboard/html/financial.html

Note the `/html/` in the URLs — there is no index page at the repo root.

## What is and isn't in this repo

Tracked: the scripts, `requirements.txt`, the three generated HTML pages, and
`cleandata/fuel_prices_idr.csv` (hand-built administered fuel prices, 2001–present,
which no script can regenerate).

Not tracked, by design:

| | Why |
|---|---|
| `rawdata/seki/` (~42 MB) | Re-downloadable — `python fetch_seki.py` |
| `rawdata/seki/clean/`, `rawdata/financial/` | Regenerated by the parsers and fetchers |
| `rawdata/ceic/` | Export from a paid CEIC subscription; not redistributable. Unused since GDP moved to the BPS API |
| `.env` | Holds `BPS_API_KEY`. **This repo is public — never commit it** |
| `econmonitor/` | Separate sub-project |

## Setting up on a new machine

Clone to **`C:\WORK\economist`**. The scripts contain ~30 hardcoded absolute paths,
so matching this location is far cheaper than refactoring them.

```
git clone https://github.com/anshory1972/econdashboard.git C:\WORK\economist
cd C:\WORK\economist
pip install -r requirements.txt
```

Create `.env` with your BPS key (register free at https://webapi.bps.go.id/):

```
BPS_API_KEY=<your key>
```

Then rebuild everything from source — no file transfer needed:

```
python fetch_gdp_bps.py        # GDP, straight from the BPS API
python fetch_financial.py      # USD/IDR + IHSG via yfinance
python fetch_seki.py           # newest SEKI edition, for BoP and prices
python parse_domain1.py && python parse_bop.py && python parse_exports.py && python parse_imports.py
python build_gdp.py && python build_bop.py && python build_financial.py
```

## Updating each quarter

GDP is decoupled from the SEKI release cycle — BPS serves the new quarter on
release day, SEKI carries it roughly two months later:

```
python fetch_gdp_bps.py && python build_gdp.py
```

BoP and prices still need SEKI:

```
python fetch_seki.py
python parse_bop.py && python parse_exports.py && python parse_imports.py
python build_bop.py
```

Then commit the changed HTML and push; GitHub Pages redeploys automatically.

## Data sources

| Page | Source |
|---|---|
| GDP | BPS WebAPI — var 65 (`turvar=237`, industry, constant 2010) and var 1956 (expenditure, constant 2010) |
| BoP | SEKI tables 5.1, 5.10, 5.19 |
| Prices / deflators | SEKI tables 7.1–7.6, 8.1, 8.2 via `parse_domain1.py` |
| Financial | Yahoo Finance via `yfinance` |

## Known issues

- `parse_exports.py` reads sheet `2010-2024` of `TABEL5_10.xls`, which BI has
  frozen. Current data now lives in the newer `5.10_1` / `5.10_2` sheets, so
  exports stop at 2024-Q2. Both trade parsers also emit partial quarters as if
  complete. **BoP Blocks 05/06 should not be published until this is fixed.**
- Several scripts are superseded and kept only for reference:
  `build_combined.py`, `build_dashboard.py`, `build_bop_dashboard.py`, and the
  `inspect_*.py` / `debug_parser.py` one-offs.
